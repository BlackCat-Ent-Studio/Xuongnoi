## Design decisions
- New entity kind `vehicle` (not a character with a flag), so combat code (Job 2) that targets characters does not hit cars by accident. Brains accept it via `liveCharacter` (now: character or vehicle).
- Collision footprint is a SQUARE (car 1.5, bike 1.2, truck 2.0; heights 0.8/0.8/1.2) so rotating never snags. Vehicles collide with blocks only. "Solid" param = solid to people on foot (walkers use blocks + solid vehicles).
- Pathfinding clearance (simplest clean design): the planners already key their grids by the entity's own body size, so a vehicle automatically plans with its 1.5 square footprint. `EntityView.drive` for vehicles = `{speed: maxSpeed, jumpPower: 0}` (no jumps planned). No planner change was needed for clearance; a test proves the car skips a 1.2 gap and takes the 3 wide one.
- Dynamics (`world/vehicles.ts`, pure): "Theo hướng" = nose turns toward the stick direction (3D stick turns with camera yaw like characters), target speed scaled by alignment; "Ga - Lái" = up gas, down brake then slow reverse, left/right steers only while rolling. Braking = 2x accel. Side view: stick sets signed speed along x, nose flips. A wall hit makes the car scrape along it (heading turns parallel, speed kept) - without this a car pressed on a pillar corner stalled forever (found in the race run).
- Seat: character glued to the vehicle (`seatedIn`), own intent ignored, camera (follows the player character) therefore follows the car. Seated look: drawn 65% tall, limbs at rest (`Humanoid.setSeated`).
- Exit spot: right, left, behind, in front (side view: behind/in front), else on the roof; each tested against solid blocks and solid vehicles. Hiding a vehicle ejects its driver; hiding a driver empties the seat.
- Node `vehicle` ports: in moveX/moveY; out self, hasDriver, speed (abs), driver. Params: position, model, steerMode, maxSpeed, accel, color, solid, control ("Người ngồi trên xe" default / "Tự chạy"). The stick only drives it when a driver sits in, so the player's WASD can feed both character and car. Node `enter-exit` (category action): in character, press (edge inside, wire Key.pressed or held); out inVehicle, vehicle; param reach 1.5.
- B2: `findPlanePath` / `findSidePath` return `{..., partial: true}` leading to the explored cell/spot closest to the goal (cap hit also counts); null only when start/goal cannot be placed. Follower stays put at the end of a partial route (no wall pushing). Side-view tests that expected null were updated to expect `partial`.
- B3: param `pathfind` ("Tìm đường", on/off, default on, LAST param of patrol, go-to, chase; missing = on) in `nodes/pathfind-param.ts`; Off = `straight: true` into `followPath` (chase flee and patrol turn-at-edge were already straight).
- Sample `race` "Đua xe về đích" (2d-top, S-track with two barriers and 3 pillars; blue player car 9 u/s, red bot car 7.5 u/s with seated robot driver started by on-start + enter-exit; win/lose via two touch nodes on the finish line). JSON generated by throwaway script (JSON is source of truth). Lesson 9 id `vehicles` "9. Lái xe" (side view, 12 steps).
